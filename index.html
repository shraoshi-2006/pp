Engineering Case Study

NetSentinel: Architecture & Deep Dive

How I designed, architected, and solved technical challenges for an autonomous network vulnerability platform.

SYSTEM ARCHITECTURE DIAGRAM // FULL DATA PIPELINE
End-to-End Vulnerability Assessment Flow
01 // THE PROBLEM

Why Build NetSentinel?

Standard vulnerability assessment tools for developers and students are either cumbersome raw terminal utilities (like Nmap) or enterprise platforms with steep paywalls that often broadcast scan results publicly. I wanted a self-contained, defensive platform where any authorized developer could audit their own perimeter, evaluate HTTP security headers, discover exposed services, and get an immediate, actionable security posture score without compromising their privacy.

02 // TECHNICAL APPROACH

Decoupled Dual-Engine Architecture

Rather than relying on a single slow scanner, I engineered a tiered discovery pipeline:

  • Socket Sweep: Multi-threaded raw socket probes for instant host discovery and common ports.
  • Nmap Deep Fingerprint: Service identification, banner grabbing, and protocol inspection executed via non-blocking background workers.
  • Header & DNS Audit: Validates HSTS, Content-Security-Policy, X-Frame-Options, and DNSSEC.
03 // CHALLENGES & SOLUTIONS

Engineering Under Constraints

  • Challenge: Scans taking 30–60s caused HTTP request timeouts.
    Fix: Implemented asynchronous FastAPI background task queues with polling status endpoints.
  • Challenge: Providing privacy without forcing visitors to create accounts.
    Fix: Automated browser session tokens via X-User-ID Axios interceptors, verified with automated pytest suites.
04 // RESULTS & LEARNINGS

What NetSentinel Taught Me

NetSentinel taught me how to handle non-blocking network I/O in Python, how to design database models that prevent multi-tenant data leakage, and the importance of presenting dense security telemetry in a way that non-security developers can understand and act upon immediately.

Cybersecurity Concepts

Attack → Defense: Engineering in Depth

Defensive cybersecurity is about reducing attack surfaces. Here are three architectural examples of how vulnerabilities are neutralized in code.

Auth & Sessions 01

Mitigating Credential Abuse & Token Replay

Attack Surface Credential stuffing, dictionary brute-forcing, and plain-text token interception over unencrypted channels.
Defense Implementation Argon2/Bcrypt password hashing, short-lived JWT tokens, HttpOnly/SameSite cookies, and strict per-IP rate limiting.
Outcome Attack surface minimized; brute-force attacks throttled; stolen client tokens rendered ineffective.
Perimeter & Headers 02

Hardening Web Perimeters & Headers

Attack Surface Exposed management ports, missing HTTP security headers, clickjacking in hidden iframes, and protocol downgrade.
Defense Implementation Automated socket/Nmap port auditing, strict Content-Security-Policy (CSP), HSTS, and X-Frame-Options: DENY.
Outcome Zero unnecessary open ports; clickjacking and cross-origin framing completely blocked at the browser layer.
Data Sanitation 03

Neutralizing SQL Injection & Bad Inputs

Attack Surface Raw string concatenations in database queries and untyped parameters leading to unauthorized data extraction.
Defense Implementation Pydantic v2 strict schema validation on all incoming payloads and SQLAlchemy parameterized ORM queries.
Outcome Malformed data rejected at the boundary; SQL injection rendered structurally impossible.
